국뽕 버프의 실효 적용을 입증하지 않는다. 뒤의 저장 실패 로그는 이 초기 51행과 별도로 기록한다.

## 7. 시작 이벤트 UI 관측과 저장 자료

국뽕팩 실행에서 시간을 진행해 1936.01.05.14의 기존 `HoK_Greatest.0` 이벤트 선택지를
실제로 선택했다. UI 정치력은 **선택 전 5 → 선택 후 1505**로 변하여 해당 관측 구간의
정치력 +1500을 확인했다. 강제 중점 완료나 정치 이념 변경을 사용한 결과가 아니다.
정치력 UI 관측을 연구 슬롯·지휘관·모든 특성의 검증으로 확대하지 않는다.

같은 1936.01.05.14 테스트에서 삼성전자(`samsung`, 국뽕 산업체)를 정치력 150으로
정상 채용했다. 채용 전후 UI와 최신 원본 화면에서 직접 관측한 범위는 다음과 같다.

| 관측 항목 | 채용 전 또는 비교 기준 | 관측 결과 |
|---|---|---|
| 산업체 채용 비용 | 정치력 1505 | 채용 후 1355: 150 소비 |
| 안정도 | 50% | 채용 후 100% |
| 전쟁 지지도 | 15% | 채용 후 100% |

UI 점수와 같은 단위라고 가정해 보너스가 달라졌다고 판단하지 않는다. 이 관측은
선택한 산업체가 연결되고 위 UI 효과가 발생했다는 범위의 증거다. 중점 전체의 연결·
정상 진행이나 국뽕 특성의 모든 modifier·MIO 장비 효과를 검증한 결과는 아니다.
이후 저장 자료의 초기·선택 후 비교와 삼성전자 활성 경로를 아래처럼 별도로 대조했다.

| 외부 기록 | 결과 | 확인 범위 |

| `runtime/runtime-preservation-comparison.json` | 162 PASS / 0 FAIL | 초기·이벤트 선택 후 저장의 선택 필드, 인물·조언가·혁신·초기화 상태 비교 |

저장 과정에서 `continue_game.temp`와 테스트 저장의 `_temp.hoi4`를 최종 이름으로
바꾸는 작업이 `errno 2`로 실패했다. 초기·선택 후 로그에 각각 기록되며, 단순히
정상 저장 완료라고 처리하지 않는다. 엔진이 남긴 완전한 텍스트 `_temp` 자료는 외부
`runtime/playset-session/runs/overlay-kor-paused/overlay-initial.hoi4`와

소유의 완전한 `_temp` 바이트를 해당 테스트의 최종 이름으로 복사한 뒤 실제 재로드에
성공했다. 이는 우회한 테스트 저장의 로드 성공이며 엔진의 일반 저장 이름 전환 실패를
해결한 것은 아니다. `errno 2`의 원인은 아직 확인하지 않았다.

### 기존 저장 이름 충돌과 복구

첫 저장 시 엔진 기본 이름이 만든 `KOR_1936_01_01_12_temp.hoi4`가 작업 전 보존 목록의

해당 기존 파일은 앞선 작업의

백업에서 복원했다. 복원 SHA-256은 작업 전 기록과 같은
`E1AAADA62CC1293896E499F55F317785D70F626A177BC07485ECD8385C7C23B7`이며,
`runtime/playset-session/save-recovery-verification.json`에서 **기존 23개 저장 모두의

후속 저장은 별도 테스트 소유의 고유 이름과 `_temp` 이름을 미리 준비하고 UI에서

저장 이름 전환 실패 자체는 미해결이라는 사실을 구분한다. 테스트에서 새로 만든 저장의

## 8. 완전 재시작과 신규 저장 재로드

기존 테스트 프로세스를 종료하고 런처의 Play로 새 PID `23600`을 시작했다. 실제 명령행은
`hoi4.exe -gdpr-compliant`인 일반 실행이며, 체크섬 `a700`·DLC 36개·활성 모드 3개를
확인했다. 콘솔 재로드나 기존 프로세스 안의 재시작으로 이 결과를 대신하지 않는다.

삼성전자 채용 후의 테스트 저장을 실제로 불러온 뒤 연구 속도 UI가 **+50005%**를
유지하는 것을 확인했다. 1936.01.10.10까지 자연 진행한 후 다시 저장했다.
외부 `runtime/reload-roundtrip-comparison.json`의 선택 필드 비교는 **136 PASS / 0 FAIL**,
`runtime/overlay-reload-structured.json`의 저장 구조 확인은 **4 PASS / 0 FAIL**이다.
이 두 수량도 앞선 정적·초기 비교·삼성전자 검사의 수량과 합산하지 않는다.

재시작·진행 후 확인한 상태는 연구 슬롯 6개, 수도 525, 네 분야 혁신 원시값 각
`300000`(UI 30), 최초 초기화 날짜를 유지한 플래그, 삼성전자 활성, 첩보원 상한 10,
지휘관 29역할의 능력치·고유 특성 집합, 조언가 17곳과 인물 ID다. 혁신 값과 플래그가
유지되어 이 새 저장의 재로드 경로에서 혁신 30이 다시 지급되지 않은 것을 확인했다.
최종 정치력은 1412.99, 지휘력은 398.67이다. 이 경로가 모든 버프 420개 원시 필드의
실효 적용, 모든 초기화 경로나 변경 전 저장의 하위 호환성을 입증하지는 않는다.

디버그 새 게임의 초기 오류 51행은 세 번의 저장 시도에서 이름 전환 실패 6행이 더해져
57행이 됐다. 완전 재시작한 일반 실행은 로드 후 50행에서 재저장 시 같은 종류의 이름
전환 실패 2행이 더해져 52행이 됐다. 진행 중 추가적인 로그 폭주는 관측하지 못했다.
디버그 통제와 일반 실행의 원시 행 수 차이를 직접 원인 비교나 오류 개선량으로 사용하지 않는다.

## 9. 종료·원복과 남은 범위

테스트 게임, 런처, `cpatch`, `dowser` 프로세스가 모두 종료된 것을 확인했다.
외부 `runtime/playset-session/after/session-restoration.json`에 다음 결과를 기록했다.

- `settings.txt`, `gameplaysettings.txt`, `pdx_settings.txt`, `dlc_load.json` 4개가 작업 전 백업과 SHA-256까지 정확히 일치한다.
- 원래 활성 플레이세트로 복원했고, 기존 플레이세트 3개의 모드 구성은 작업 전과 같다.
- 새 테스트 플레이세트는 사용자 허가로 만든 3모드 활성 구성을 그대로 보존했다.
- 기존 저장 23개의 최종 해시가 작업 전과 같으며 테스트 소유 저장 6개만 외부 `after/test-saves/`로 보관했다.
- 올바른 하이픈형 저장소 경로와 `picture`를 적용한 로컬 국뽕팩 `.mod` 수정은 유지한다. 이 의도적인 연결 수정까지 과거의 잘못된 값으로 되돌리지는 않았다.

Steam에는 이전 실행 추적의 중지 중 표시가 남아 UI에서 정상 종료한 뒤 재시작했다.
이후 HOI4 라이브러리의 녹색 **플레이** 버튼 복귀를 확인했다. 재시작 후에도 설정 4개의
정확한 백업 해시, 기존 플레이세트 3개의 멤버십, 기존 저장 23개의 작업 전 해시가 모두
유지됨을 다시 확인했다. 마지막 상태는 `runtime/playset-session/after/final-ui-and-profile.json`과
`runtime/playset-session/current-preservation-check.json`에 기록했다.
게임·런처·`dowser`·`cpatch` 프로세스가 없음을 최종 재확인했다.

테스트가 남긴 `continue_game.temp`는 내용이 테스트의 reload 저장만 가리킴을 확인한 뒤
외부 `after/test-saves/`로 보관했다. 실사용 저장이나 원래 프로필의 다른 파일을 임의로
정리한 것은 아니다. 올바르게 수정한 로컬 `.mod`와 새 테스트 플레이세트는 유지했다.

1.19.2 하위 호환성, 기존 대문자 인물 ID가 들어간 저장의 호환성, 다른 북마크·DLC 조합,
장기 AI·멀티플레이 동기화와 모든 제조사/MIO·특성 효과는 미검증이다.
원본 저장소와 게임 설치 파일은 수정하지 않았다. 테스트 자료·백업은 외부 경로에 보관했으며
커밋·푸시·Workshop 작업은 수행하지 않았다.
