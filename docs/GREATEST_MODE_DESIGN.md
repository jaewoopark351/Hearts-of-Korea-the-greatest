# `Hearts of Korea the Greatest` 강화 설계

## 1. 제품 목표

한국으로 시작했을 때 이미 세계 최상위 연구·산업·군사·첩보 기반을 가진다는 판타지를
명확하게 구현한다. 사용자가 요구한 핵심 결과는 다음과 같다.

- 육군·해군·공군·산업·전자·핵 관련 일반 연구가 빠짐없이 완료되어 있다.
- 육군·해군·공군·원자력 연구시설이 모두 존재하고 정상 작동한다.
- 선택한 범위의 특수 프로젝트가 완료되어 있거나 즉시 완료할 수 있다.
- 첩보 준비뿐 아니라 작전 실행 기간 자체가 눈에 띄게 짧다.
- 최강 프리셋 본체 효과는 한국에만, 게임당 한 번만, 선택한 게임 규칙에서만 적용된다.
- 단, `GRT-211`의 시작 혁신 포인트 30 지급은 사용자 결정에 따라 게임 규칙과 분리된
  상시 계승판 보너스로 취급한다.

최강 프리셋 본체는 밸런스 복원이 아니라 의도적인 초강력 플레이 옵션이다. 따라서 복원 기본값과
섞지 않고 `GOOKPPONG_GREATEST_ENABLED`라는 별도 게임 규칙 선택지로 제공한다.
이 이름은 가칭이며 ID 충돌 조사 후 확정한다.

새 규칙 파일을 중복 생성하기보다는 기존
`common/game_rules/hok_game_rules.txt`의 `kor_gookppong_status`에 최상위 선택지를
추가하는 방향을 우선한다. 기존 실제 option ID는 `DEFAULT`,
`GOOKPPONG_MIDDLE_POWER_ENABLED`, `GOOKPPONG_ENABLED`다.

## 2. 프리셋 구조

| 프리셋 | 목적 | 연구 상태 | 게임 성격 |
|---|---|---|---|
| 비활성/복원 | 원작 보존과 호환성 기준선 | 원작 수준 | 검증·멀티 기준 |
| 중간 강국 | 기존 `middle_power` 보존 | 일부 시작 보너스 | 완화된 강화 |
| 구버전 국뽕 | 기존 `gookppong` 보존 | 일부 기초 기술·슬롯 | 레거시 체험 |
| **최강 한국** | 이번 프로젝트 목표 | 허용된 일반 기술·교리·프로젝트 완성 | 명시적 파워 판타지 |

최강 프리셋 본체는 기본값으로 강제하지 않는다. 이렇게 해야 복원 상태와 의도적인 치트성
밸런스를 한 프로젝트에서 비교하고 검증할 수 있다. `GRT-211`은 이 원칙의 범위를 넓히는
것이 아니라, 별도로 승인된 단일 상시 시작 보너스다.

## 3. 완료 기준

### GRT-001 — 적용 범위

- `GRT-211`의 독립 시작 보너스를 제외하고, 게임 규칙에서 최강 프리셋을 선택한 경우에만
  실행한다.
- 수신 스코프가 한국(`KOR`)인지 확인한다.
- `hok_greatest_initialized_v1` 같은 버전 플래그로 한 번만 실행한다.
- 저장 후 재로드, 내전, 합병, 정부 변경으로 다시 보너스가 중첩되지 않는다.
- AI 한국에도 적용할지는 게임 규칙 설명에 명시한다. 권장 기본은 선택한 프리셋이면
  사람/AI를 동일하게 처리해 멀티플레이 동기화를 단순화하는 것이다.

### GRT-100 — 일반 기술 전체 완료

일반 기술은 대상 버전의 `common/technologies`를 기준으로 다음 묶음을 각각 감사하고
명시적 허용 목록으로 지급한다.

- 산업·건설·생산·합성 자원
- 전자·레이더·암호·컴퓨팅
- 보병·지원중대·포병·대공·대전차
- 기갑 및 전차 설계 관련 기반 기술
- 해군 함체·모듈·상륙·기뢰 관련 기술
- 공군 기체·엔진·무장·지원 기술
- 로켓·제트·원자력의 일반 기술 부분

구현 원칙:

1. `research all` 같은 콘솔 명령을 스크립트 효과라고 가정하지 않는다.
2. 대상 버전에서 실제 등록되는 기술 ID만 `set_technology` 허용 목록에 넣는다.
3. DLC 전용 기술은 동일 DLC 조건 안에서만 지급한다. NSB 전차 트리와 legacy 전차
   트리, BBA 항공 트리와 legacy 항공 트리, MtG 해군 트리와 legacy 해군 트리를 동시에
   지급하지 않는다.
4. 숨김용·테스트용·더미·타국 전용·상호 배타 기술은 자동 수집에서 제외한다.
5. 게임 업데이트마다 기술 목록 diff를 만들고 신규/삭제 ID를 검토한다.
6. 기술 지급과 장비 변형 지급을 분리한다. 기술이 있다고 기존 변형 ID가 자동 생성되는
   것은 아니다.

`ledger = army/air/navy` 표기는 연구 bonus category가 아니다. 제한 연구 보너스가
필요하면 대상 DB에 등록된 `infantry_weapons`, `infantry_tech`, `armor`, `artillery`,
`support_tech`, `air_equipment`, `plane_modules_tech`, `naval_equipment`,
`ship_modules_tech`, `nuclear` 같은 실제 category를 사용한다. 모든 일반 연구 속도는
별도의 `research_speed_factor` 축이다.

#### 연도 범위

최강 프리셋은 시작 연도와 관계없이 현재 대상 버전에 존재하는 허용 기술을 모두
완료하는 것을 목표로 한다. 이는 후반 기술을 1936년에 여는 의도적인 설계다. 기술창에
연구할 항목이 거의 남지 않는 것도 정상 결과로 문서화한다.

시작 연구 슬롯은 총 6개를 기준안으로 삼고, 단순 `add_research_slot` 누적이 아니라
최종값과 기존 중점 보상을 함께 설계한다. 최강 프리셋에서는 이미 6개라면 이후 슬롯
중점이 연구 보너스, 돌파구 또는 과학자 보너스로 대체되어야 한다. 모든 현재 기술이
완료된 뒤 빈 슬롯이 생기는 것은 오류가 아니며, 미래/추가 모드 기술을 위한 여유다.

### GRT-110 — 교리 완성

교리는 일반 기술과 별도다. 상호 배타 분기를 모두 억지로 활성화하지 않는다.

권장 UX:

- 최초 이벤트 또는 결정에서 육군·해군·공군 교리 노선을 각각 고른다.
- 선택한 노선은 끝까지 완성한다.
- 선택하지 않은 상호 배타 노선은 잠긴 상태를 유지한다.
- 선택 화면을 원하지 않으면 한국의 기본 최강 노선을 문서로 확정한 뒤 고정한다.

가칭 기본안:

- 육군: 현대 화력·기동 중심 노선
- 해군: 항모 전단 또는 잠수함/해상차단 중 하나
- 공군: 제공권과 근접항공지원 중심

실제 효과 키와 분기 ID는 1.19 바닐라 교리 DB를 대조해 확정한다. 1.19 생성 문서에서
확인된 `set_grand_doctrine`, `set_sub_doctrine` 체계를 사용하되, 그 문서의 예시 ID가
실제 DB보다 오래된 경우가 있으므로 예시를 그대로 복사하지 않는다. 과거
`set_technology` 방식의 교리 ID도 그대로 복사해서는 안 된다.

확인한 1.19.2 실제 대교리 ID 예:

- 육군: `new_mobile_warfare`, `superior_firepower`, `grand_battleplan`, `mass_assault`
- 해군: `new_fleet_in_being`, `new_convoy_raiding`, `new_base_strike`
- 공군: `new_strategic_destruction`, `new_battlefield_support`, `new_operational_integrity`

### GRT-200 — 네 종류 연구시설

반드시 제공할 시설:

- `land_facility`
- `naval_facility`
- `air_facility`
- `nuclear_facility`

이 시설 체계를 사용하는 효과는 `has_dlc = "Gotterdammerung"`에 해당하는 대상 버전
바닐라 사례로 감싼다. DLC가 없을 때는 존재하지 않는 건물/프로젝트를 호출하지 않고
일반 연구와 기존 연구 보너스만 제공한다.

구현 원칙:

- 커스텀 지도에서 한국이 소유·통제하고 있는 유효한 주와 프로빈스를 먼저 찾는다.
- 해군 시설은 해안 조건을 확인한다.
- 같은 그룹의 시설 최대치와 기존 시설 유무를 확인한 뒤 건설한다.
- 올바른 주 스코프에서 `add_building_construction`의 1.19 바닐라 예시를 따른다.
- 고정 주 ID를 사용한다면 지도 변경 시 깨지는지 별도 검사한다.
- 시설이 이미 있으면 두 번 추가하지 않는다.

시설 배치 제안:

| 분야 | 배치 원칙 | 테마 |
|---|---|---|
| 육군 | 수도권 또는 내륙 산업 중심지 | 국방과학연구소 |
| 해군 | 검증된 남·동해안 프로빈스 | 해군기술연구원 |
| 공군 | 비해안 강제 조건 없이 안전한 산업 주 | 항공우주연구원 |
| 원자력 | 후방 내륙, 높은 공급과 방어가 가능한 주 | 국가원자력연구단지 |

정확한 주/프로빈스 ID는 커스텀 지도 감사 전에는 확정하지 않는다.
테마 후보 프로빈스는 서울 `7125`, 인천 `7221`, 부산 `4056`, 대전 `11977`이지만,
시설별 위치 제약과 커스텀 지도의 실제 소유·통제·해안 상태를 확인하기 전에는 구현에
사용하지 않는다.

### GRT-210 — 과학자와 돌파구

- 네 분야 모두 최소 1명의 유효한 과학자를 확보한다.
- 기존 한국 과학자와 특성, 초상화, 현지화 키를 우선 재사용한다.
- 원본의 핵 분야 과학자는 보존하되, 육·해·공 분야 인력이 실제로 등록되는지 확인한다.
- 분야별 돌파구 진행도 또는 포인트를 충분히 제공한다.
- 시설에 과학자를 실제 배치할 수 있는지 UI에서 확인한다.
- 인물이 중복 모집되거나 사망/은퇴 상태에서 다시 생성되지 않게 한다.

### GRT-211 — 독립 시작 혁신 포인트

상태: **[NEW] 정적 구현 완료, 런타임 미검증**
결정일: 2026-09-03

이 항목은 전체 최강 프리셋 초기화와 분리된 단일 시작 보너스다. 새 게임을 시작하면 기존
`kor_gookppong_status`의 선택값과 관계없이 한국에 혁신 포인트를 지급한다.

요구사항:

- 구현 파일은 `common/on_actions/hok_greatest_breakthrough_on_actions.txt`다.
- 원본의 `common/on_actions/gookppong_on_actions.txt`와 같은 상대 경로를 사용하지 않는다.
  같은 이름을 쓰면 의존 모드의 큰 원본 파일을 가상 파일시스템에서 가릴 수 있다.
- 엔진에 이미 등록된 `on_startup` 콜백에 독립 효과를 추가한다. 임의 이름의 자동 실행
  on_action을 새로 정의하는 방식이 아니다.
- `on_startup` 자체는 특정 국가 스코프가 아니므로 효과 안에서 `KOR`로 전환한다.
- 게임 규칙 조건은 넣지 않는다. 사람 한국과 AI 한국 모두 대상이며 다른 국가는 대상이 아니다.
- `add_breakthrough_points`의 `specialization = all`, `value = 30`을 사용한다.
- 이 효과는 값을 30으로 설정하는 것이 아니라 기존 값에 30을 더한다.
- `all`은 현재 네 전문 분야인 육군·해군·공군·원자력에 각각 30점을 뜻하므로 총 지급량은
  120점이다.
- 새 게임 초기화에서만 실행한다. 기존 세이브를 불러오는 것만으로는 소급 지급하지 않는다.
- 향후 다른 초기화 경로에서 같은 효과를 호출하더라도 중복 지급되지 않도록 전용 국가
  플래그 `hok_greatest_breakthrough_initialized_v1`로 보호한다. 현재 대상과 원본에서 이
  ID의 충돌은 발견되지 않았다.

현재 구현 형태는 다음과 같다.

```txt
# [NEW] Independent KOR startup breakthrough points.
#20260903_kpopmodder
on_actions = {
    on_startup = {
        effect = {
            KOR = {
                if = {
                    limit = {
                        NOT = {
                            has_country_flag = hok_greatest_breakthrough_initialized_v1
                        }
                    }

                    add_breakthrough_points = {
                        specialization = all
                        value = 30
                    }

                    set_country_flag = hok_greatest_breakthrough_initialized_v1
                }
            }
        }
    }
}
```

근거 수준:

- **확인됨**: HOI4 1.19.2 생성 문서에서 `add_breakthrough_points`는 `COUNTRY` 스코프를
  지원하고 `specialization = all`을 허용한다.
- **확인됨**: 1.19.2의 `common/on_actions/_documentation.md`에 `on_startup`이 등록되어
  있으며, 바닐라의 여러 독립 파일이 같은 콜백에 효과를 누적한다.
- **확인됨**: 현재 전문 분야 ID는 `specialization_land`, `specialization_naval`,
  `specialization_air`, `specialization_nuclear` 네 개다.
- **미검증**: 이 프로젝트의 실제 플레이셋에서 새 게임 직후 네 분야가 각각 30으로 표시되는
  런타임 결과는 구현 후 확인해야 한다.
- **미검증**: `Gotterdammerung` 미보유 플레이셋의 UI와 오류 없는 동작은 별도 부정 경로로
  확인한다. 근거 없이 DLC 조건을 먼저 추가하지 않는다.

### GRT-220 — 특수 프로젝트 완료

사용자 요구인 “연구 관련 전부 완료”는 최강 프리셋에서 다음처럼 정의한다.

> 보유 DLC와 현재 게임 버전에서 한국이 합법적으로 사용할 수 있는 일반 기술을 모두
> 완료하고, 상호 배타·국가 전용·테스트용 항목을 제외한 특수 프로젝트 허용 목록을
> 모두 완료한다.

프로젝트 처리 순서:

1. 네 시설과 과학자를 준비한다.
2. 프로젝트 선행 일반 기술을 지급한다.
3. 선행 프로젝트부터 위상 정렬한 순서로 완료한다.
4. `is_special_project_completed`로 중복 완료를 막는다.
5. `complete_special_project = sp:<project_id>`의 대상 버전 형식을 프로젝트별로
   사용한다.
6. 각 완료가 발생시키는 보상, 프로토타입, 이벤트, 장비 변형을 확인한다.

1.19 생성 문서에 따르면 `complete_special_project`는 프로젝트 선행조건을 무시하고,
시설 주나 과학자에 붙은 효과를 대신 적용하지 않는다. 그러므로 명령 성공만으로 전체
연구 체인이 정상 완료됐다고 판단하면 안 된다. 원자로 연구시설인 `nuclear_facility`와
핵무기 생산 건물인 `nuclear_reactor`도 서로 구분한다.

`complete_special_project`에 모든 프로젝트를 뜻하는 `all` 인수를 줄 수 있다는 근거는
없으므로 프로젝트 ID를 하나씩 명시한다. 반면 분야별 돌파구 효과의
`specialization = all` 지원은 확인되었지만, 네 분야별 지급량과 결과를 따로 기록하는
편이 검증에 유리하다.

원자력의 시작 관문인 `atomic_research`, 원자로 프로젝트, 핵폭탄 프로젝트, 고급 DLC
프로젝트를 선후 관계대로 별도 목록화한다. 프로젝트가 `nuclear_reactor` 건물, 핵 1개,
장비/프로토타입 같은 산출물을 주는지도 acceptance matrix에 기록한다. 기술 완료,
프로젝트 완료, 생산 건물, 실제 핵무기 보유를 같은 상태로 취급하지 않는다.

프로젝트를 즉시 끝내지 않는 시설 완성형에서는 `special_project_speed_factor`와
`specialization_nuclear_speed_factor` 등 실제 분야별 속도 키를 사용한다. 일반
`research_speed_factor`, 시설 건설 속도, 특수 프로젝트 속도는 각각 별도 축이다.

두 가지 내부 프로필을 유지하면 디버깅이 쉽다.

- `시설 완성형`: 시설·과학자·돌파구만 최고 수준으로 주고 프로젝트 UI는 남긴다.
- `완전체 시작형`: 검증된 프로젝트 허용 목록까지 모두 완료한다. 최종 사용자 요구는
  이 프로필이다.

완전체 시작형에서도 상호 배타 결과를 동시에 주어 UI나 장비 DB를 망가뜨리는 항목은
제외 목록에 넣고 문서에 이유를 기록한다.

### GRT-300 — 초고속 첩보

정보기관 단계의 목표:

- La Résistance 보유 여부를 먼저 확인하고, 정보기관이 없으면
  `create_intelligence_agency`의 대상 버전 형식으로 생성한다.
- 기관이 생긴 뒤에만 검증된 ID를 `upgrade_intelligence_agency`로 적용한다.
- 필요한 기관 업그레이드를 완료하거나 업그레이드 시간을 사실상 즉시 수준으로 줄인다.
- 충분한 요원 슬롯과 한국인 요원을 제공한다.
- 정보망 성장, 암호 해독, 방첩, 작전 비용·위험·결과를 최상위 수준으로 강화한다.

초기 목표 수치 제안은 밸런스 기준이 아니라 최강 프리셋의 체감 기준이다.

| 항목 | 목표 체감 | 초기 조정안 |
|---|---|---|
| 기관 업그레이드 | 거의 즉시 | 시간 90~95% 감소 |
| 정보망 | 며칠 내 작전 준비권 진입 | 획득량 3~5배 |
| 실제 작전 속도 | 장기 작전도 수 주 이내 | 속도 3~5배 후보 |
| 작전 비용 | 부담이 거의 없음 | 75~90% 감소 |
| 작전 위험 | 요원 손실이 드묾 | 75~90% 감소 |
| 작전 결과 | 유리한 결과가 일반적 | 결과 보정 대폭 증가 |
| 암호 | 주요국보다 우위 | 해독력·암호 강도 대폭 증가 |

수치는 실제 modifier 단위와 clamp를 확인한 후 확정한다. 음수 0.9가 90% 감소인지,
다른 보너스와 합쳐 어디에서 제한되는지를 게임에서 검증해야 한다.

#### 실제 작전 기간 단축

작전 `days` 단축은 위의 준비·비용 modifier와 별도 요구사항이다. 1.19.2 생성 문서에서
실제 작전 속도용 `intelligence_operation_speed`가 확인되었다. 우선순위는 다음과 같다.

1. 한국 정보기관 범위에 `intelligence_operation_speed`를 양수로 적용한다.
2. 원시 수치가 실제 날짜에 미치는 영향을 대표 작전별로 바닐라 대조군과 비교한다.
3. 목표는 75~180일 작전을 대략 15~45일 체감으로 줄이는 것이며, 실제 계산과 clamp에
   따라 수치를 조정한다.
4. modifier가 해당 범위에서 작동하지 않을 때만 자주 쓰는 바닐라 작전을 새 한국 전용
   ID로 복제하는 대안을 검토한다.
5. 대안에서도 한국 전용 작전은 `KOR`와 최강 게임 규칙에서만 표시되게 한다.
6. 바닐라 작전 ID를 재정의하거나 `common/operations/00_operations.txt` 전체를
   `replace_path`로 덮지 않는다.
7. 작전별 준비일, 실행일, 후속 이벤트 간격을 실제 UI와 로그에서 확인한다.

정확한 역할 분담은 `agency_upgrade_time`이 기관 업그레이드,
`intel_network_gain_factor`가 정보망, `intelligence_operation_speed`가 실제 작전 속도,
`operation_cost`/`operation_risk`/`operation_outcome`이 비용·위험·결과다. 하나의 키로
모든 첩보 단계가 빨라진다고 가정하지 않는다.

일부 1.19.2 바닐라 사보타주 작전 정의에는 generic `operation_risk`와
`operation_outcome`이 위험/결과 목록에 서로 뒤바뀐 것으로 보이는 항목이 있다.
따라서 국가 modifier가 모든 작전에 똑같이 반영된다고 단정하지 않고, 침투·기술 탈취·
협력정부·산업/인프라/자원 사보타주를 각각 시험한다.

### GRT-400 — 육·해·공군 즉시 전력화

모든 기술만 열고 생산 기반이 없으면 체감이 약하다. 2차 강화 범위로 다음을 권장한다.

- 육군: 현대식 사단편제, 지원중대, 충분한 장비 비축, 지휘관과 교리
- 공군: 검증된 최신 기체 변형, 조종사/연료 기반, 주요 공항 수용력
- 해군: 최신 함체와 모듈 변형, 해군기지·수리 능력, 연료와 숙련 승조원
- 미사일/핵: 사용 가능한 무기, 투발 수단, 저장고 및 생산 조건

장비·함정·기체 변형은 DLC 설계 시스템에 따라 구조가 달라진다. 존재하지 않는 모듈을
참조하거나 같은 변형 ID를 두 번 등록하지 않도록 기술 지급과 별도 파일/단계로 둔다.

### GRT-500 — 경제와 보급

최강 군사 기술이 실제로 작동하도록 선택적으로 제공한다.

- 건설·생산·조선·항공 생산 능력
- 자원 부족을 막을 최소한의 국내 자원 또는 무역 보정
- 연료 생산·저장·소비 보정
- 수도와 주요 산업지의 철도·보급망
- 연구시설이 작동할 전력과 공급

커스텀 지도 자원과 건물을 대량 수정하는 것은 고위험이다. 우선 국가 아이디어와
검증된 시작 건설 효과로 해결하고, 주 파일 자체 변경은 별도 지도 작업으로 분리한다.

### GRT-600 — AI 정책

- 최강 프리셋이 플레이어 전용이면 `is_ai = no` 정책과 UI 설명을 일치시킨다.
- AI 한국에도 적용한다면 산업·전자·공군·해군·원자력·프로젝트 우선순위를 보완한다.
- 이미 완료된 기술을 AI가 계속 우선시하지 않는지 확인한다.
- 지급한 최신 장비 기술과 AI 생산라인, 사단·함대·비행단 편제가 서로 맞아야 한다.
- 사람 한국과 AI 한국의 초기화 경로를 달리할 경우 멀티플레이 동기화 영향을 검사한다.

## 4. 권장 스크립트 구조

아래 파일명은 구현 시 사용할 수 있는 제안이며 아직 생성하지 않는다.

```text
common/
  game_rules/
    hok_game_rules.txt                  # 기존 kor_gookppong_status 확장
  on_actions/
    hok_greatest_breakthrough_on_actions.txt # GRT-211 독립 시작 30점
    hok_greatest_on_actions.txt              # 향후 선택형 최강 프리셋 본체
  scripted_effects/
    hok_greatest_initializer.txt
    hok_greatest_technologies.txt
    hok_greatest_doctrines.txt
    hok_greatest_facilities.txt
    hok_greatest_projects.txt
    hok_greatest_intelligence.txt
    hok_greatest_equipment.txt
  ideas/
    hok_greatest_ideas.txt
  operations/                         # 속도 modifier가 실패할 때만 대안
    hok_greatest_operations.txt
events/
  hok_greatest_events.txt
localisation/korean/
  hok_greatest_l_korean.yml
```

기존 거대 `gookppong_on_actions.txt`에 모든 기능을 더 넣지 않는다. 초기화 파일은
작은 scripted effect들을 정해진 순서로 호출하고, 각 모듈은 독립적으로 재검증할 수
있어야 한다.

권장 호출 순서:

```text
게임 규칙 확인
  -> KOR 스코프 확인
  -> 버전 플래그 확인
  -> 일반 기술
  -> 교리
  -> 시설과 과학자
  -> 특수 프로젝트
  -> 첩보
  -> 장비 변형과 비축
  -> 경제·보급
  -> 완료 플래그와 요약 이벤트
```

## 5. 기술 허용 목록 관리

“모든 연구”가 업데이트 때 다시 누락되지 않도록 허용 목록을 데이터로 관리한다.

각 항목에 기록할 필드:

- 기술/프로젝트 ID
- 분야
- 도입 버전
- 필요한 DLC
- 선행 ID
- 상호 배타 그룹
- 한국 사용 가능 여부
- 지급 효과 파일
- 정적 검증 결과
- 런타임 검증 결과
- 제외 시 사유

목록은 대상 버전 바닐라와 diff할 수 있어야 한다. 자동 스캔은 후보를 만드는 용도이며,
후보 전부를 자동 지급하면 안 된다.

## 6. UI와 설명

게임 규칙 설명에는 다음 사실을 숨기지 않는다.

- 최강 프리셋은 밸런스를 의도적으로 파괴한다.
- 현재 버전의 후반 기술과 프로젝트가 시작 즉시 열린다.
- 일부 상호 배타/타국 전용/내부 프로젝트는 안전상 제외된다.
- 멀티플레이에서는 모든 참가자가 동일한 모드 버전을 사용해야 한다.
- 업적과 바닐라 체크섬을 기대할 수 없다.

시작 후 요약 이벤트에서 지급된 기술 수, 선택 교리, 건설된 시설, 완료 프로젝트 수,
적용된 첩보 보너스를 보여주면 누락을 사용자가 바로 확인할 수 있다.

## 8. 검증 시나리오

### GRT-211 전용 긍정 경로

1. `kor_gookppong_status = DEFAULT`로 1936 한국 새 게임을 시작한다.
2. 육군·해군·공군·원자력 혁신 포인트가 각각 30인지 확인한다.
3. 기존 진행도가 있다면 지워지지 않고 포인트만 30 증가했는지 확인한다.
4. 한국 AI에도 동일하게 적용되는지 확인한다.
5. 저장 후 재로드해도 60점으로 중복되지 않는지 확인한다.
6. 같은 플레이셋의 다른 국가에는 혁신 포인트가 지급되지 않는지 확인한다.
7. `error.log`에 새 scope, effect, on_action 관련 오류가 없는지 확인한다.

### 필수 긍정 경로

1. 최강 프리셋으로 1936 새 게임을 시작한다.
2. 한국에 효과가 정확히 한 번 적용되는지 확인한다.
3. 일반 기술 탭별 미완료 목록을 내보내 허용된 항목이 0개인지 확인한다.
4. 선택한 육·해·공 교리가 끝까지 완료되었는지 확인한다.
5. 네 시설이 지도와 프로젝트 UI에 존재하는지 확인한다.
6. 네 분야 과학자를 배치할 수 있는지 확인한다.
7. 프로젝트 허용 목록과 완료 목록을 대조한다.
8. 대표 첩보 작전의 준비일·실행일을 바닐라 대조군과 비교한다.
9. 저장, 재로드, 한 달 진행 후 효과가 중복되지 않는지 확인한다.

### 필수 부정 경로

- 비활성 프리셋에서는 `GRT-211`의 독립 30점 외에 최강 프리셋 본체 강화가 적용되지 않는다.
- 중간/구버전 프리셋은 기존 수치와 동작을 유지한다.
- 다른 국가는 혁신 포인트를 포함한 기술·시설·첩보 보너스를 받지 않는다.
- DLC가 없을 때 해당 기술/프로젝트 참조 오류가 나지 않는다.
- 한국이 존재하지 않거나 해방되는 특수 시나리오에서 초기화가 폭주하지 않는다.

### 완료로 볼 수 없는 결과

- 메인 메뉴가 열림
- `error.log` 줄 수가 감소함
- 연구창 일부가 채워짐
- 시설 아이콘만 보임
- 정보망이 빨라졌지만 작전 `days`는 그대로임

실제 요구사항별 결과를 확인해야 최강 프리셋 완료로 판정한다.

## 9. 주요 위험과 대응

| 위험 | 결과 | 대응 |

| 모든 기술 ID 무차별 지급 | 숨김/상호 배타 기술 충돌 | 검토된 허용·제외 목록 |
